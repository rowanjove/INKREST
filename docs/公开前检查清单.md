# GitHub 公开前检查清单

私有仓库可以随时在 GitHub 设置中改为公开，但公开会让默认分支、标签、发布附件和可达提交历史一起变得可见。执行前至少完成以下检查。

## 代码与历史

- 扫描当前文件和完整 Git 历史中的密钥、令牌、邮箱、用户名、私人作品名与本机绝对路径。
- 确认 `.env`、模型配置、项目数据库、正文、日志、备份和桌面构建物从未进入历史。
- 如果历史中存在敏感内容，先轮换相关密钥，再使用干净公开历史或经过复核的历史重写；不要只删除最新版本中的文件。
- 检查所有标签和发布附件，确认它们不包含本地配置、数据库、日志或私人作品。

## 授权与社区文件

- 选择并加入开源许可证；公开可见本身不等于授权他人使用。
- 明确贡献方式、支持范围和安全问题报告渠道。
- 检查第三方字体、图标、图片、提示词、示例文本与依赖的再分发许可。
- 确认项目名、图标和品牌素材可以公开使用。

## 产品与安全

- 使用全新临时数据目录运行应用，验证首次启动不会依赖开发者机器上的文件。
- 使用示例密钥占位符验证配置说明，不在截图、终端输出或发布说明中出现真实密钥。
- 确认默认只监听回环地址，远程监听必须启用访问令牌。
- 验证项目删除、备份、重置、插件安装和模型请求都需要清晰的用户操作。
- 对桌面包运行清单检查，排除数据库、日志、缓存、测试结果和开发工具。

## 发布与可见性

- 运行仓库规定的后端、前端、端到端、性能与打包门禁。
- 为准备公开的版本生成变更记录，并校验版本号、标签和应用元数据一致。
- 先在私有状态下检查 GitHub 仓库首页、README 图片、发布页和下载附件。
- 开启适合的分支保护、依赖更新和安全扫描设置。
- 切换为公开后，使用未登录窗口复查仓库与发布页实际可见内容。
