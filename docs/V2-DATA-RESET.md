# V2 项目备份与重置

栖墨 V2 提供项目级、备份优先的重新开始流程。它不等同于“清空整个应用”，
也不会触碰其他项目或全局模型配置。

## 入口

打开“设置 → 系统与数据 → 项目数据维护”：

- **仅创建备份**：输入 `BACKUP <project_id>`。
- **备份并重置到 V2**：输入 `RESET V2 <project_id>`。

后端要求确认语逐字符匹配。项目存在活跃或持久化未完成任务时返回 409，
不会绕过保护。

## 备份内容

备份 ZIP 包含当前项目的：

- `data/`
- `state/`
- `workspace/`

ZIP 在完成后执行 CRC 测试并计算 SHA-256、文件数和字节数。以下内容主动排除：

- `.env`、模型密钥与凭据文件
- `logs/`
- `plugins/`
- 外部符号链接
- `__pycache__/`

备份默认位于项目根的同级目录 `backups/v2-reset/`，不写入 Git。

## 重置范围

创建并验证备份后，服务清理当前项目的运行时目录：

`data`、`state`、`workspace`、`logs`、`dashboard`、`exports`、`dist`、`build`。

随后创建干净目录与 schema version 2 的 SQLite。以下项目内容保留：

- `config/`
- `assets/`
- `prompts/`
- `plugins/`
- 书名、描述、封面和注册表元数据

## 安全保证

- 项目必须存在于 `projects.json`，且路径必须是 `projects/` 的直接子目录。
- 拒绝路径穿越、项目目录符号链接和指向项目外的链接。
- 重置使用隔离目录；中途失败会回滚原运行时。
- 切换、删除和重置会释放项目级任务管理器，避免后台轮询继续访问旧库。
- API 与 UI 不会把“只清理叙事表”描述为“删除所有数据”。

## 恢复

恢复目前是显式运维操作：

1. 关闭栖墨，确认项目没有运行任务。
2. 保留当前项目目录副本。
3. 校验备份 SHA-256。
4. 只把需要的 `data/`、`state/`、`workspace/` 解压到目标项目。
5. 重新启动后检查 schema 与项目快照。

不要把一个项目的备份覆盖到另一个项目 ID；不要从备份中恢复任何密钥。
