# V2 Phase 4：正文中心与文档模型重构计划

> 日期：2026-07-27  
> 分支：`codex/v2-refactor`  
> 范围：正文数据真相层、三栏正文中心、自动保存、AI 建议审阅、历史版本、阅读预览，以及旧章节页面的兼容收敛。

## 目标

把目前互相重叠的章节列表、章节详情、写作工作台、阅读器、分支版本和文件快照整合成一个正文中心：

1. SQLite 中的 Tiptap JSON 是正文唯一权威来源；
2. 纯文本、Markdown 和 `chapter_final.txt` 只作为派生内容与旧流水线兼容投影；
3. 左侧目录、中间编辑器、右侧上下文/AI/审校/历史共用一个可调整工作区；
4. 保存默认自动完成，并用 `revision` 拒绝静默覆盖并发修改；
5. AI 结果先以建议差异展示，只有用户明确采纳才写入编辑器；
6. 版本、快照、分支统一为可预览、可恢复的文档历史；
7. `/writer`、`/chapters`、`/chapters/:id` 的旧入口最终都进入同一正文中心。

## 社区组件决策

- `@tiptap/vue-3`、`@tiptap/pm`、`@tiptap/starter-kit`、`@tiptap/extension-placeholder` 固定为 `3.29.0`。采用官方 Vue 3 集成和 JSON 文档输出，不引入付费云服务。
- `@tanstack/vue-virtual` 固定为 `3.13.34`。用于长篇作品的章节目录虚拟滚动，并以稳定章节 ID 作为 item key。
- 继续复用 `splitpanes@4.1.2` 实现三栏尺寸调整和持久化。
- Element Plus 只承载菜单、标签、抽屉、确认和反馈；不再用 `textarea` 冒充正文编辑器。

## 非目标与安全边界

- 本阶段不触发续写、章节生成、批量生产或任何真实模型调用。
- AI 改写、润色、扩写、续写只建立“提出意图 → 显示确认 → 请求建议 → 预览差异 → 明确采纳”的 UI 契约；自动化测试仅使用 mock。
- 不在本阶段清空用户项目数据。新文档首次读取时可从旧正文文件惰性导入，Phase 7 再执行用户已授权的项目级重置。
- 不把编辑器内部 JSON、文件路径、版本 UUID 或原始技术状态暴露给普通模式用户。
- 不删除生产、审校、发布阶段仍在消费的文件投影。

## 完成标准

- SQLite Tiptap JSON 是正文唯一权威来源，旧文本文件只由保存服务派生。
- 两个客户端同时编辑时，过期修订保存返回明确冲突，不会静默覆盖。
- 正文中心中间编辑区默认占据主空间，目录和辅助信息均可折叠、调整和恢复。
- 正文变化无需用户反复点击保存；保存中、已保存、离线/失败、冲突状态始终可见。
- AI 结果在采纳前不会修改正文，采纳后可通过历史恢复。
- 普通用户不再需要在章节列表、详情、写作工作台和阅读器之间往返完成正文工作。
- 页面无横向溢出，键盘可操作，深色主题一致，完整质量门禁通过。
