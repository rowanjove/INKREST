# V2 Phase 7：旧数据重置、残留清理与最终交付计划

> 日期：2026-07-27
> 分支：`codex/v2-refactor`
> 前置：Phase 0—6 已完成并通过各阶段验收
> 用户授权：允许清空旧数据重新开始

## 目标

完成 V2 的最后一次收口：把误导性的旧数据清理入口替换为可验证、先备份的项目级 V2 重置；删除已经失去引用的页面、组件、工具和导出表面；修复依赖声明；在精确备份后重置旧项目运行时；最后从干净依赖环境完成全量、性能、无障碍、桌面和打包验收。

## 安全边界

- 不触发小说生成、审核、重写、批量任务或模型调用。
- 不删除全局模型配置、API Key、`.env`、插件或项目外部路径。
- 用户旧项目逐项目生成 CRC 与 SHA-256 均通过的去密钥备份，再重置运行时目录。
- 活跃任务项目不重置；先报告并停止，不绕过任务保护。
- 仓库、worktree、用户主目录和磁盘根目录永远不作为递归删除目标。
- 清理候选必须同时满足：无活动引用、替代路径通过测试、删除后完整构建通过。

## 任务 1：建立最终基线与可复现审计

- [ ] 记录主仓库、V2 worktree 和桌面用户数据目录中的项目/运行时清单、schema、大小与活跃任务。
- [ ] 使用 Knip 查找 Vue/TypeScript 未引用文件、导出与依赖。
- [ ] 使用 Vulture 高置信度模式查找 Python 疑似死代码。
- [ ] 对候选使用 `rg`、路由/入口和测试逐项复核，不自动采用工具删除建议。
- [ ] 记录社区工具选择与误报边界。

## 任务 2：替换误导的数据管理入口

- [ ] 新增项目级备份与 V2 重置前端 API。
- [ ] 用 `ProjectDataMaintenance` 替换旧 `DataManager`。
- [ ] 显示当前项目名称和 ID，解释保留项、清理项与备份位置。
- [ ] “仅备份”要求输入 `BACKUP <project_id>`。
- [ ] “备份并重置”要求输入 `RESET V2 <project_id>`，调用后端原子重置并重新 hydrate。
- [ ] 活跃任务、确认词错误、无项目和后端失败均给出准确错误，不宣称“全部数据已清空”。
- [ ] 加入前端单测/源码契约和 API 回归。

## 任务 3：删除确定无用的前端与兼容残留

- [ ] 删除 Knip 发现且经引用检查确认无入口的旧组件、store、barrel 和工具。
- [ ] 把仍在使用的 `OutlineEditorLegacy` 改为中性 `OutlineEditor`，不把有效功能当成旧功能删除。
- [ ] 清理仅服务已删除组件的级联依赖和自动生成组件声明。
- [ ] 删除确定无调用方的前端 API 导出；保留 CLI、插件和明确兼容入口。
- [ ] 把 `@element-plus/icons-vue` 声明为直接生产依赖，不再依赖传递安装。
- [ ] 保留 Electron 主进程入口、更新器、宠物 IPC 和安全模块；将 Knip 的多入口误报配置为审计例外。

## 任务 4：收敛 Python/文档残留

- [ ] 处理 Vulture 100% 置信度且确认真实的死代码；抽象方法参数和可选依赖探测不按误报删除。
- [ ] 复核旧 schema/YAML 镜像/`web.server` bridge；只删除无活动引用的层，不破坏插件和 CLI。
- [ ] 更新 `PROJECT.md`、`PROJECT_STRUCTURE.md`、`README.md`、状态真源和数据重置说明。
- [ ] 文档不再把已删除页面、旧组件或“不可恢复清空”描述为当前能力。

## 任务 5：执行已授权的受控旧数据重置

- [ ] 对桌面用户数据目录中每个旧项目执行空闲检查。
- [ ] 为每个项目生成去密钥、去日志、去插件、拒绝外部符号链接的备份并验证 SHA-256。
- [ ] 逐项目执行 V2 重置，确认 schema version 2、运行时目录为空且项目隔离不受影响。
- [ ] 清理主仓库和 V2 worktree 中由测试生成的项目、数据库、状态、日志与工作区产物。
- [ ] 对仓库根级旧单项目运行时先生成受控备份，再清理。
- [ ] 输出备份位置、摘要、文件数与重置结果；不输出密钥内容。

## 任务 6：干净安装与最终验收

- [ ] 在临时 Python 3.12 虚拟环境安装生产锁和构建锁，执行导入/启动/五格式烟测。
- [ ] 运行 Ruff、完整后端测试、API 性能基线和显式 E2E。
- [ ] 运行关键页面无障碍与键盘导航检查。
- [ ] 重建 PyInstaller sidecar 和 `electron-builder --win --dir`。
- [ ] 运行打包 Electron renderer 烟测、五格式包内导出、单实例和敏感文件清单检查。
- [ ] 确认 Git 工作区干净、无密钥/运行时数据进入提交。

## 完成标准

- 数据管理 UI 与实际行为一致，默认先备份，所有 destructive scope 都是项目级且可审计。
- 旧项目运行时已安全重置到 schema V2；备份可定位、可校验且不含密钥/日志/插件。
- 确定无引用的旧页面、组件、store、工具和 API 表面已删除；有效功能不因名字含 `Legacy` 被误删。
- 生产依赖直接声明完整；干净安装可以重建并运行。
- 后端、前端、Electron、E2E、性能、无障碍、bundle、依赖审计和 Windows 打包全部通过。
- V2 分支无未提交改动、无用户配置/项目数据/构建产物进入 Git。
