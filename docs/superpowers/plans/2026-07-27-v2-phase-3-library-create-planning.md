# V2 Phase 3：书库、创建流程与策划中心重构计划

> 日期：2026-07-27  
> 分支：`codex/v2-refactor`  
> 范围：书库、新建作品、项目概览、策划中心，以及支撑这些页面的统一故事实体读取模型。

## 目标

把目前分散的书库操作、首次使用向导、三种创建入口、套路线工坊、人物资产、大纲、状态与关系图整合为四个清晰入口：

1. 书库负责选择和管理作品；
2. 新建作品用一个四步流程完成创作模式、素材来源、写作规格和建档确认；
3. 项目概览只展示决策信息和下一步，不复制生产控制台；
4. 策划中心用“实体树—画布—检查器”承载大纲、人物、地点、组织、物品、伏笔、规则、关系和时间线。

## 社区组件决策

- `@vue-flow/*`：统一关系图、卡片大纲和时间线的节点、边、缩放、选择、控制器与小地图，不再维护多套坐标和画布交互。
- `splitpanes`：提供可拖动、键盘可访问的三栏布局，避免自制分隔条和尺寸持久化逻辑。
- 只引入上述两类基础设施；表单、菜单、对话框和状态组件继续复用现有 Element Plus 与 V2 UI primitives。

## 非目标

- 本阶段不触发章节生成、批量生产或自动续写。
- 不迁移或删除现有项目数据；统一读取模型先兼容现有文件和 SQLite 状态。
- 不在本阶段重写正文编辑器、生产控制台和发布流程。

## 完成标准

- 用户不会再看到两个首次使用/建书向导或独立套路线工坊入口。
- 书库卡片没有散落的管理按钮，关键信息在一个视野内可比较。
- 大纲、人物、世界设定、剧情状态和关系不再是互不相干的页面。
- 所有现有数据都能被策划中心读取；空项目也能稳定进入并获得明确下一步。
- 页面无横向溢出，键盘可操作，深色主题一致，全套质量门禁通过。

## 完成记录

完成日期：2026-07-27。

实现结果：

- 书库改为可比较的紧凑作品卡，管理动作统一进入单一菜单；浏览器验收发现并修复了菜单点击冒泡误开项目的问题。
- 首次引导、快速创建、AI 引导、大纲导入和套路模板合并为四步建档流程；建档前只保存草稿，不触发小说生成。
