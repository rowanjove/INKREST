# WriterHelper 提示词与小说项目格式逆向笔记

> 逆向对象：本仓库本地安装包 `dist/extension.js` 的格式化副本 `reverse/extension.pretty.js`，以及明文资源 `resources/novelWorkbench_types_typing.md`。

## 1. 小说项目目录

插件把小说工作台数据放在工作区根目录下：

```text
.writerHelper/
├── prompt-settings.json              # 提示词覆盖/增强配置
├── knowledge_base/                   # 工作台 Agent 可搜索的知识库
└── novelWorkbench/
    ├── outline.json                  # 大纲
    ├── outline_details.json          # 细纲/卷章结构
    ├── settings.json                 # 工作台全局设置、绑定文件、自定义类型等
    ├── rules.json                    # 写作规则
    ├── works.json                    # 作品列表，资源类型文档中出现
    ├── settings/
    │   ├── characters.json           # 人物
    │   ├── world.json                # 世界
    │   ├── skills.json               # 技能
    │   ├── items.json                # 物品
    │   ├── scenes.json               # 场景
    │   └── factions.json             # 势力
    ├── timelineNetwork/              # 代码里的新版时间线存储
    │   ├── meta.json
    │   ├── edges.json
    │   ├── nodes/
    │   │   ├── character.json
    │   │   ├── item.json
    │   │   ├── setting.json
    │   │   ├── story.json
    │   │   ├── foreshadow.json
    │   │   └── hook.json
    │   └── node_descriptions/
    │       └── <nodeId>.json
    └── types/
        └── typing.md
```

注意：`resources/novelWorkbench_types_typing.md` 写的是单文件 `timelineNetwork.json`，但 `reverse/extension.pretty.js:240194` 之后的实际读写逻辑已经拆成目录式 `timelineNetwork/`。

## 2. 核心 JSON 格式

### outline.json

```ts
interface OutlineConfig {
  summary: string;
  conflict: string;
  sellingPoint: string;
  worldView: string;
  volume_outline?: Record<string, string>;
  outline: Record<string, {
    person: string[];
    site: string[];
    info: string;
  }>;
  meta?: {
    updatedAt: number | string;
    sourcePaths: string[];
    sourceMtimes: Record<string, number | string>;
    changeRanges?: Record<string, Array<{
      startLine: number;
      endLine: number;
      timestamp: number | string;
    }>>;
  };
}
```

代码实际保存时主要保留 `summary/conflict/sellingPoint/worldView/outline/meta`，见 `reverse/extension.pretty.js:240236`。

### outline_details.json

```ts
interface OutlineDetailsConfig {
  volumes?: Array<{
    id: string;
    name: string;
    summary?: string;
    chapters: Array<{
      id: string;
      name: string;
      title?: string;
      summary?: string;
      characters?: string[];
      settings?: string[];
      locked?: boolean;
      filePath?: string;
      plotDescription?: string;
    }>;
  }>;
  meta?: ConfigMeta;
  [key: string]: any;
}
```

如果没有卷，插件会自动补一个 `{ name: "第一卷", summary: "", chapters: [] }`，见 `reverse/extension.pretty.js:240262`。

### settings/*.json

六个内置设定类型本质都是数组：

```ts
type SettingItem = {
  name: string;
  description?: string;
  [key: string]: any;
};

type CharactersConfig = SettingItem[];
type WorldConfig = SettingItem[];
type SkillsConfig = SettingItem[];
type ItemsConfig = SettingItem[];
type ScenesConfig = SettingItem[];
type FactionsConfig = SettingItem[];
```

高亮器会读取这些文件中的 `name` 并在文稿中标色，内置类型为 `characters/world/skills/items/scenes/factions`。

### settings.json

明文类型文档只写了：

```ts
interface SettingsConfig {
  tabHighlightColors?: Partial<Record<
    "characters" | "world" | "skills" | "items" | "scenes" | "factions",
    string
  >>;
}
```

代码里还会使用：

```ts
interface SettingsConfigRuntime {
  tabHighlightColors?: Record<string, string>;
  boundFiles?: Record<string, string[]>;  // 一键绑定/同步文档
  customTypes?: Array<{ id: string; name: string; [key: string]: any }>;
  [key: string]: any;
}
```

### rules.json

```ts
interface RulesConfig {
  commonWords: Array<{ id: string; content: string; description?: string }>;
  commonSentences: Array<{ id: string; content: string; description?: string }>;
  forbiddenWords: Array<{ id: string; content: string; description?: string }>;
  forbiddenSentences: Array<{ id: string; content: string; description?: string }>;
  writingTechniques: string;
  referenceAuthors?: any[];
  savedAt?: number;
}
```

`referenceAuthors` 是代码实际保存时额外支持的字段，见 `reverse/extension.pretty.js:240307` 和 `reverse/extension.pretty.js:719697`。

### timelineNetwork 新版运行时格式

```ts
interface TimelineNetworkRuntime {
  nodes: {
    character: TimelineNode[];

  [key: string]: any;
}
```

## 3. 提示词系统

提示词管理器在 `reverse/extension.pretty.js:678371`。内置模块数组为：

```js
var Bq = [rDA, nDA, sDA, oDA, cDA, lDA, uDA];
```

运行时调用：

```js
Oe.getInstance().getCompiledPrompt(featureId, "system")
```

拼接规则：

1. 默认取内置 `feature.system.prompt`。
2. 如果 `.writerHelper/prompt-settings.json` 有 `customSupplement`，它会替换默认 system prompt。
3. 如果有 `associatedPrompts`，会追加为“增强提示词”。
4. 最后追加 `feature.system.structure`。
5. `feature.user` 可单独取，但很多功能直接重新组 user prompt。

`prompt-settings.json` 的形态大致是：

```json
{
  "rewrite": {
    "customSupplement": "覆盖默认 system prompt",
    "associatedPrompts": [
      { "id": "xxx", "title": "增强提示词标题", "content": "增强内容" }
    ],
    "temperature": 0.8,
    "topP": 0.9
  }
}
```

## 4. 内置 prompt 模块清单

### 章节生成模块 `chapterGen`

位置：`reverse/extension.pretty.js:676115`

主要 feature：

- `chapter`：完整章节正文生成。核心风格是“专业长篇网络小说作家”，要求续写、不要总结、承接上一章、目标字数 `{wordCount}`、章节号 `{chapterNumber}`，并内置大量“去 AI 味”禁用词和格式限制。
- `chapterSummary`：章节 Markdown 总结，固定输出“章节概述、人物发展、看点/爽点、故事伏笔、收尾特征、张力心电图、总体评分”。
- `plotDeduction`：剧情推演，返回 JSON `{ title, content }`。
- `reviewPlot`：剧情审查，返回 `{ summary, items[] }`，每项包含 `id/title/description/location/severity/suggestion/selected`。
- `reviewWriting`：写作手法审查。
- `reviewCharacter`/其他 review 类：围绕人设、节奏、伏笔等做审查。
- `chapterSummaryDeduce` / `chapterSummaryRefresh`：根据大纲、章纲、前后章摘要推演或刷新章节梗概。
- `extractNetwork`：从章节正文抽取时间线网络，返回 `nodes/relations/recoveredForeshadows`。

### 文本分析/资料拆解模块

位置大约：`reverse/extension.pretty.js:676557` 到 `677770`

主要 feature：

- `extraction`：结构化信息提取，返回 `characters/relationships/world/events`。
- `storyline`：故事线拆解，分析主线、支线、核心冲突、世界观、写作习惯、核心卖点等。
- `chapterAnalysis`：章节分析，输出章节概括、故事脉络、伏笔、钩子、人物变化等。
- `characterKm`、`worldKm` 等：生成 KityMinder `.km` JSON 思维导图。

### 划词 AI 工具栏

调用位置：`reverse/extension.pretty.js:703128`、`703209`、`703642`

featureId：

- `rewrite`：AI 改写
- `expand`：AI 扩写
- `continue`：AI 续写
- `simplify`：AI 精简
- `customDescribe`：自定义描写
- `aiFlavorRemove`：祛除 AI 味

这些功能大多要求返回段落级 diff JSON：

```json
{
  "paragraphs": [
    {
      "index": 0,
      "modified": ["修改后的内容"],
      "type": "modified",
      "tips": ["修改原因"]
    }
  ]
}
```

`type` 常见取值：`modified`、`split`。祛味只允许 `modified`。

### 诊断类 prompt

位置：`reverse/extension.pretty.js:704000` 起。

- `typos`：错别字检查，片段级 JSON 诊断。
- `readingExperience`：阅读感诊断。
- 错别字全文修正：内联 system prompt，要求只修错别字，不改段落结构。
- 阅读感全文优化：内联 system prompt，优化长段落、语句不通、上下文断层、节奏、人称视角、重复冗余、敏感内容。
- AI 味诊断：通过 `aiFlavorService`，结果用于 `paragraph_details` 高亮，字段包括 `ai_score/reason/range` 等。

### 图形化 prompt

位置：`reverse/extension.pretty.js:723885`

featureId：

- `graphCharacters`
- `graphScenes`
- `graphSkills`
- `graphItems`

输入是绑定的设定文档内容，输出图数据：

```json
{
  "nodes": [
    { "id": "node-id", "label": "显示名", "name": "名称" }
  ],
  "edges": [
    { "from": "node-id", "to": "node-id", "label": "关系" }
  ]
}
```

## 5. 小说工作台 Agent prompt

位置：`reverse/extension.pretty.js:720222`

工作台聊天/Agent 会根据当前面板类型拼接不同 system prompt：

- `outline`：身份是“深耕网络小说平台二十余年的顶流金番作者”，强调番茄平台、黄金三章、强情绪爽点、新奇脑洞、世界观闭环。
- `chapterOutline`：身份是“网络小说章纲创作专家”，强调卷结构、黄金三章、爽点节奏、每章留钩子，且要求参考前面章节保持连续性。
- `settings`：身份是“网络小说设定设计师”，关注人物、世界观、技能体系、物品、场景、势力。
- `rules`：身份是“网络小说写作规范专家”，关注词汇、句式、禁用词句、写作手法、对标作者。
- `foreshadows`：身份是“伏笔与钩子设计专家”，关注伏笔埋设、回收、章末钩子。

Agent 还有强制工作流：

- 先调用读取工具获取资料，优先 query 精确检索，不一次性读全量。
- 如果用户要求修改配置，必须调用 `update_*` 工具，不要把完整 JSON 或 operations 当普通文本返回。
- `update_*` 入参统一是：

```json
{
  "operations": [
    {
      "type": "update",
      "path": "sellingPoint",
      "object": "新的内容"
    }
  ]
}
```

`type` 支持 `add/delete/update`，`path` 是点号 JSON 路径，如 `volumes.0.chapters.0.title`。

## 7. 导入/同步相关 prompt

### 细纲文本识别

位置：`reverse/extension.pretty.js:716707`

AI 只分析前 4000 字样本，返回：

```json
{
  "volumeNameRegex": "卷名正则",
  "chapterNameRegex": "章节名正则",
  "example": {
    "volumeName": "示例卷名",
    "chapterName": "示例章节名"
  }
}
```

然后代码用这个正则拆分全文，形成 `volumes[].chapters[]`。

### 大纲文本识别

位置：`reverse/extension.pretty.js:717845`

AI 返回提取规则：

```json
{
  "worldView": { "pattern": "规则", "description": "说明" },
  "summary": { "pattern": "规则", "description": "说明" },
  "conflict": { "pattern": "规则", "description": "说明" },
  "sellingPoint": { "pattern": "规则", "description": "说明" },
  "fallback": true
}
```

但代码目前基本仍把全文作为 `summary`，如果缺 `worldView/conflict/sellingPoint`，再调用补全 prompt，返回：

```json
{
  "worldView": "200-300字世界观",
  "conflict": "100-200字核心冲突",
  "sellingPoint": "100-200字核心卖点"
}
```

### 写作规则生成

位置：`reverse/extension.pretty.js:719629`

输入多章正文，要求只抽取写作手法、句式、词汇选择和语言风格，不要抽人物名、地名、物品名、专有名词。返回：

```json
{
  "commonWords": [{ "content": "词汇1", "description": "说明" }],
  "commonSentences": [{ "content": "句式1", "description": "说明" }],
  "forbiddenWords": [{ "content": "词汇1", "description": "为什么禁止" }],
  "forbiddenSentences": [{ "content": "句式1", "description": "为什么禁止" }],
  "writingTechniques": "详细的写作手法和风格总结"
}
```

代码保存时会自动补 `id`、`savedAt`。

## 8. 关键占位符

已确认出现的 prompt 占位符：

- `{chapterNumber}`：章节号
- `{wordCount}`：目标字数
- `{randomSeed}`：剧情推演随机种子
- `{CHAPTER_CONTENT}`：章节正文
- `{EXISTING_FORESHADOWS}`：已有伏笔列表

## 9. 最适合复刻的最小数据模型

如果要做一个兼容 WriterHelper 工作台的数据生成器，最小只需要生成：

```text
.writerHelper/novelWorkbench/
├── outline.json
├── outline_details.json
├── settings.json
├── rules.json
└── settings/
    ├── characters.json
    ├── world.json
    ├── skills.json
    ├── items.json
    ├── scenes.json
    └── factions.json
```

时间线如果要兼容当前代码，按目录式 `timelineNetwork/` 写入；如果只按明文类型文档写 `timelineNetwork.json`，新版代码未必会读取。
