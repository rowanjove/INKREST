# 体量自适应小说生成系统架构设计

> 不是做一个超长篇系统，是做一个按体量自动选择架构的调度系统。
> 用户感知到的是同一个入口，系统内部按档位加载完全不同的生成逻辑。

---

## 一、设计原则

不同体量的小说，信息层次需求完全不同：

```
一章短篇    根本不需要大纲层，直接生成
十章短篇    需要简单起承转合，不需要卷层
百章中篇    需要完整四层大纲
千章长篇    需要分形结构，卷动态生成
无限流      需要容器+副本隔离架构
```

用同一套架构强行兼容所有体量，要么短篇系统过重，要么长篇写到后期崩。

**解法：同一个入口，按体量动态选择架构预设。**

---

## 二、体量档位定义

| 档位 | 体量 | 典型场景 |
|------|------|---------|
| 微型 | 1-3章 | 热点快速出内容，单场景故事 |
| 短篇 | 5-20章 | 完整小故事，单一故事弧 |
| 中篇 | 30-100章 | 标准网文，完整三幕结构 |
| 长篇 | 100-500章 | 分卷结构，卷动态生成 |
| 超长篇 | 500章以上 | 分形结构，状态分级压缩 |
| 无限流 | 不设上限 | 容器+副本隔离，理论无限 |

用户不需要理解档位概念，只需回答一个问题：

```
"你大概想写多长？"

  一章以内 / 几章 / 几十章 /
  一两百章 / 几百上千章 / 一直更新下去
```

系统将答案映射到档位，加载对应架构。

---

## 三、各档位架构设计

### 微型（1-3章）

**定位**：热点驱动，快速出内容，系统开销极小。

```
大纲层：无
状态层：无
向量召回：无

生成流程：
  L0类型基因 → 一次调用直接生成完整内容

单次调用同时输出：
  场景设定 + 角色设定 + 完整正文
```

---

### 短篇（5-20章）

**定位**：完整小故事，一次规划完所有章节。

```
大纲层：
  L0 类型基因层
  L3 章节序列（一次性规划全部章节，不滚动）

状态层：
  仅高频状态，不分级

向量召回：不启用

全书脊梁简化为：
  核心冲突：一句话
  结局方向：HE / BE / 开放
  全部章节序列：一次生成完毕
```

---

### 中篇（30-100章）

**定位**：系统最标准形态，完整四层大纲 + 完整信息层。

```
大纲层：完整四层
  L0 类型基因层
  L1 全书骨架层（含四个锚点）
  L2 卷级大纲（按三幕结构切2-3卷）
  L3 章节序列（滚动窗口，每次规划15-20章）

状态层：完整三频
  高频：每章更新（场景/角色当前状态）
  中频：每5-10章更新（关系网络/势力格局）
  低频：关键节点更新（伏笔账本/秘密分布）

向量召回：启用
规划窗口：15-20章滚动
节奏配比：硬约束（每10章爆发章≥2个）
校准机制：每20章自动校准
```

---

### 长篇（100-500章）

**定位**：分卷结构，放弃全书终点规划，卷动态生成。

```
大纲层：
  L0 类型基因层
  L1_lite 全书层（只保留方向，不设终点锚点）
  L2_dynamic 卷层（每卷50-100章，卷结束前动态生成下一卷）
  L3 章节序列（滚动窗口）

全书层极简内容：
  世界核心矛盾（推动故事的底层张力）
  主角永恒驱动（贯穿全书的行为底色，不是目标）
  成长方向（只设方向，不设终态）
  世界规则边界（什么是不可能的）

卷层动态生成规则：
  当前卷剩余10章时，自动生成下一卷大纲
  下一卷基于当前世界状态和主角状态生成
  卷与卷之间只连接，不预设

状态层：两级压缩
  热状态：最近20章，完整保留
  温状态：20-100章之前，压缩为里程碑事件列表

角色管理：三级
  核心角色：完整状态，始终在context中
  活跃角色：完整状态，卷结束时压缩为快照
  休眠角色：只保留快照，再次出场时恢复

向量召回：启用
  温状态内容入向量库
```

---

### 超长篇（500章以上）

**定位**：分形结构，每一个局部都是完整的，局部之间有连接，但不在开始时规划所有局部。

```
大纲层：
  L0 类型基因层
  L1_minimal 全书层（极简，仅世界矛盾+主角驱动）
  L2_dynamic 卷层（动态生成，不预设卷数）
  L3 章节序列（滚动窗口）

状态层：四级压缩
  热状态：最近20章，完整保留，直接进入context
  温状态：20-100章之前，压缩为里程碑事件列表
  冷状态：100章以前，压缩为人物志/世界志词条
  归档：已完结剧情线，不再参与召回

压缩触发时机：
  每写完1章   → 更新热状态
  每写完10章  → 最旧10章热状态压缩为温状态
  每写完50章  → 最旧50章温状态压缩为冷状态
  卷结束时    → 本卷冷状态整合进人物志/世界志
              → 已完结剧情线归档

角色管理：四级
  核心角色：始终在context中
  活跃角色：当前卷完整状态
  休眠角色：快照，不进入context
  归档角色：一条人物志词条，不再参与生成

向量库：
  冷状态+归档内容全部入库
  超过50章的章节摘要降低召回权重

校准机制：每20章自动执行
  对比全书层方向 vs 实际进度
  检查伏笔账本过期风险
  输出调整建议
```

---

### 无限流（不设上限）

**定位**：容器+副本隔离架构，副本结算机制保证系统永远轻装运行。

```
架构层次：

  容器层（永久固定，初始化时生成一次）
    系统规则：任务触发/积分计算/死亡规则/通关条件
    主角成长框架：能力维度/阶段门槛（不设具体数值，设框架）
    副本类型库：现代/古代/末世/游戏/etc 及各类型特有规则
    主角核心性格：贯穿所有副本不变的行为底色

  主线层（可选，跨副本长期叙事线）
    核心谜题：需要跨多个副本才能解开的秘密
    主线进度：每个副本结束后揭露多少
    主线节奏：每N个副本必须推进一次
    终态（模糊）：大概指向什么方向，不需要精确

  副本层（每副本独立生成，20-50章）
    副本编号/类型/世界规则
    核心任务/难点设计
    主要NPC（副本结束即归档）
    爽点类型/副本钩子/预计章节数

  章节层（副本内滚动规划）
    与中篇章节层相同

状态隔离规则：

  副本外持久状态（跨副本保留）：
    主角能力等级
    主角持有的资源/道具
    主线信息碎片
    与系统/组织的关系

  副本内临时状态（副本结束即清空）：
    副本内角色关系
    副本内世界状态
    副本内具体事件记录

副本结算机制（副本结束时执行）：
  1. 提取副本收益 → 写入持久状态
  2. 提取副本摘要（100字以内）→ 写入向量库
  3. 清空副本内临时状态
  4. 归档副本内NPC
  5. 生成下一副本的副本层大纲

副本生成策略：
  难度递增：主角能力等级 + 副本编号 → 决定基础难度
  类型轮换：同一大类副本完成后，至少间隔2个副本才能再出现
  节奏变化：每5个副本里，至少1个轻松类 + 1个高压力类
  爽点不重复：与最近3个副本的爽点类型不同
```

## 四、档位对比总览

| 维度 | 微型 | 短篇 | 中篇 | 长篇 | 超长篇 | 无限流 |
|------|------|------|------|------|--------|--------|
| 大纲层数 | 无 | L0+L3 | L0-L3完整 | L0+L1精简+L2动态+L3 | L0+L1极简+L2动态+L3 | 容器+副本 |
| 全书规划 | 无 | 一次规划完 | 完整四锚点 | 只规划方向 | 极简方向 | 无全书概念 |
| 状态层 | 无 | 单级 | 三频 | 热/温两级 | 热/温/冷/归档四级 | 持久/临时隔离 |
| 向量召回 | 否 | 否 | 是 | 是 | 是 | 是（副本摘要） |
| 压缩机制 | 无 | 无 | 无 | 两级 | 四级 | 副本结算 |
| 角色管理 | 无 | 无 | 无分级 | 三级 | 四级 | 持久/副本NPC |
| 崩溃风险 | 极低 | 极低 | 低 | 中（状态膨胀） | 中（靠压缩缓解） | 极低（隔离机制） |
| 理论上限 | 3章 | 20章 | 100章 | 500章 | 2000-3000章 | 无限 |

## 五、体量升级机制

用户开始写短篇，写着写着想继续——这是网文创作的常态。系统必须支持体量升级，不要求重新建项目。

### 升级触发

```
自动触发：章节数接近当前档位上限时，系统提示"是否继续扩展？"
手动触发：用户随时可以选择"扩展这部小说"
```

### 升级路径

**短篇 → 中篇**
```
1. 补生成 L1 全书骨架（基于已有内容反向提炼）
2. 补生成 L2 卷级大纲
3. 初始化向量库（已有章节摘要批量入库）
4. 状态层从单级升级为三频
```

**中篇 → 长篇**
```
1. 全书骨架的终点锚点标记为"模糊"
2. 启用卷层动态生成
3. 状态层从三频升级为热/温两级压缩
4. 已有状态按时间线重新分级
```

**长篇 → 超长篇**
```
1. 启用冷状态和归档级别
2. 对已有温状态执行一次批量压缩
3. 校准机制启用
```

**长篇/中篇 → 无限流转型**
```
1. 将现有故事封装为"第一副本"
2. 生成容器层（系统规则/成长框架/类型库）
3. 提取主角持久状态
4. 清理原有临时状态
5. 后续按副本结构运行
```

## 六、架构配置文件设计

每个档位是一个独立的架构配置，系统按档位加载：

```yaml
# scale_micro.yaml
scale: micro
max_chapters: 3
outline_layers: []
state_layers: []
vector_enabled: false
planning_mode: single_shot

# scale_short.yaml
scale: short
max_chapters: 20
outline_layers: [L0, L3]
state_layers: [high_freq]
vector_enabled: false
planning_mode: full_upfront

# scale_medium.yaml
scale: medium
max_chapters: 100
outline_layers: [L0, L1, L2, L3]
state_layers: [high_freq, mid_freq, low_freq]
vector_enabled: true
planning_window: 20
calibration_interval: 20

# scale_long.yaml
scale: long
max_chapters: 500
outline_layers: [L0, L1_lite, L2_dynamic, L3]
state_layers: [hot, warm]
vector_enabled: true
planning_window: 20
compression: two_tier
episode_volume: 50-100  # 每卷章节数

# scale_epic.yaml
scale: epic
max_chapters: unlimited
outline_layers: [L0, L1_minimal, L2_dynamic, L3]
state_layers: [hot, warm, cold, archive]
vector_enabled: true
planning_window: 20
compression: four_tier
calibration_interval: 20
compress_hot_every: 10    # 每10章压缩一次热状态
compress_warm_every: 50   # 每50章压缩一次温状态

# scale_infinite.yaml
scale: infinite
structure: container_episode
max_chapters: unlimited
container_layer: true
optional_mainline: true
episode_chapters: 20-50
episode_isolation: true
settlement_on_episode_end: true
type_cooldown: 2          # 同类副本冷却间隔
payoff_cooldown: 3        # 同类爽点冷却间隔
```

## 七、统一入口的调度逻辑

```
用户新建项目
    ↓
选择大概体量（一句话选项，用户不感知档位概念）
    ↓
系统映射到对应档位
加载对应架构配置
    ↓
热点分析 → 方向选择 → 按档位初始化
    ↓
开始生成

运行中：
    ↓
章节数接近档位上限
    ↓
系统提示是否升档
    ↓
用户确认 → 执行升档迁移 → 继续生成
用户拒绝 → 标记为"封闭式结局"→ 进入收尾规划
```

## 八、设计原则总结

| 原则 | 说明 |
|------|------|
| **档位自适应** | 按体量加载不同架构，不用同一套强行兼容 |
| **短篇轻装** | 微型/短篇不启用大纲层和状态层，直接生成 |
| **长篇分形** | 放弃全书终点规划，卷层动态生成，局部完整 |
| **超长篇压缩** | 四级状态压缩，防止历史信息膨胀 |
| **无限流隔离** | 副本内外状态严格隔离，结算机制保证轻装运行 |
| **升档无缝** | 体量升级不重建项目，系统自动迁移状态和大纲 |
| **用户透明** | 所有架构复杂度对用户隐藏，入口始终一致 |
